# Project submission

## Name

OnTheHook

## One-liner

Semantic consensus turns each binding promise into either a closed result claim/rebuttal pair or a permanently open two-sided effort log.

## Notes / Description

OnTheHook asks what a promise puts its author on the hook for: a particular end state, or only the manner of its own conduct. GenLayer validator consensus classifies the text once. The result then selects one of two deterministic record shapes. RESULT_OWED allows one permanent discharge claim from the author and one rebuttal from the named other side; log entries are unavailable. EFFORT_OWED creates a two-sided append-only log that never gains a completed state; discharge and rebuttal are unavailable. The interface places both live records side by side, keeps all four actions visible, and shows the contract’s exact reason when a method does not exist for that shape. State comes from the deployed StudioNet contract; there is no seeded data, preview classifier, money custody, clock, or external web input.
